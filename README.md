# ChatGPT 2FA 与中转站管理工具

在 Windows 本机运行的中文网页工具，提供批量更换 2FA、加密历史记录、Sub2API OAuth 接入和失效账号重授权。

## 首次使用

1. 安装 Python 3.11、3.12 或 3.13，并将 Python 加入 PATH；安装 Google Chrome。
2. 下载并解压本仓库，或使用 Git 克隆。
3. 双击 **首次安装.cmd**，创建本机 Python 环境并安装依赖。
4. 双击 **启动2FA工具.cmd**，打开 <http://127.0.0.1:5033/>。

源码不包含账号、管理员 Key、历史数据或预装的 Python 环境。首次安装需要联网，Windows 登录自启动需在自己的电脑上另行设置，方法见 [使用说明.md](使用说明.md)。

## 功能

- 多行批量输入，单批最多 500 个不同账号，逐个执行。
- 没有历史记录的账号优先处理。
- 有历史账号支持再次更换，默认先确认；可保存“无需确认”的默认选项。
- 批次状态、成功与失败记录自动加密保存，刷新后仍可查。
- 左侧历史记录支持邮箱搜索、状态筛选、分页与结果复制下载。
- 原有成功恢复记录导入历史；中断任务按原操作继续，避免重复解绑。
- 可选在更换后退出不同城市／地区的活动会话，保留当前及同地点会话。
- 自动处理密码登录入口、2FA 输入和已识别的首次使用引导；验证码错误会显示具体原因。
- 连接 Sub2API，配置分组、并发、优先级、工作空间、指纹收敛和订阅档位等账号选项。
- 自动完成正常 OAuth 登录和回调；只有个人账户与一个其他工作空间时，自动选择其他空间。
- 加密保存中转站地址及管理员 Key，支持导入当前账号资料、手动重授权和定时检查 401。

人机验证、额外邮箱验证码和无法唯一确定的工作空间仍需在浏览器中处理。账号登录资料应由账号所有者提供或授权使用。

输入和每条结果格式均为 `邮箱----密码----2FA密钥`。更换保持密码原值，输入应为当前有效密钥。

具体使用见 [使用说明.md](使用说明.md)。

## 文件

| 路径 | 用途 |
| --- | --- |
| `web_tool.py` | 本机 API、来源隔离与启动入口 |
| `batch_manager.py` | 批量队列、确认、历史查询及恢复 |
| `history_store.py` | 加密原子历史存储 |
| `web/` | 中文网页界面 |
| `relay_*.py` | 中转站连接、账号配置、OAuth、重授权和定时检查 |
| `local_tool.py` | 单个账号的更换与恢复流程 |
| `private_state.py` | Windows DPAPI 与跨进程锁 |
| `session_phase.py`、`chatgpt_auth/`、`mfa_phase.py` | 现有登录与 2FA 实现 |
| `runtime/history.dpapi` | 批次、记录、结果和设置的加密文件 |
| `runtime/private/` | 各账号当前操作的加密恢复记录 |
| `.venv/` | 首次安装时创建的本机 Python 环境，不随源码分发 |
| `requirements-local.txt` | 本地依赖清单 |

手动启动：

```text
.venv\Scripts\python.exe web_tool.py --open
```

仅监听 `127.0.0.1:5033`，重复启动复用当前项目服务。中断的 2FA 批次需要在页面中继续；已开启的定时重授权在后台启动后恢复检测。默认设置只影响后续新批次，已有待确认批次仍需显式确认或跳过。

## 数据保存

历史文件保存账号输入与成功结果，使用当前 Windows 用户加密；普通列表和进度接口不返回密码或密钥，完整结果通过明确的结果操作读取。登录 token 和 cookie 不进入历史。

每条任务执行前持久化，已验证结果及时归档。服务重启时核对相同操作的恢复记录并标记未完成任务，不把历史成功误当作新一轮成功。

不要删除 `runtime` 来重试。加密数据绑定当前 Windows 用户，复制到另一台电脑或另一个用户后不能直接解密。分享源码时应排除整个 `runtime`、`.venv`、`.git` 和缓存目录；仓库中的忽略规则已排除本机运行数据。
